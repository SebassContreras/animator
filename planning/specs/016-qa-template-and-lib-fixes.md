## Requirements
- R1 (`F-01`): `videos/_template/scene.gen.cjs:10` resolves `../brand.lock.json` first and falls back to local `./brand.lock.json` only when `../brand.lock.json` does not exist (matching standalone `videos/_template/` execution).
  - Partitions:
    - Brand video folder `videos/<brand>/<video>/` where `../brand.lock.json` exists and no local `brand.lock.json` exists → loads `../brand.lock.json`.
    - Brand video folder `videos/<brand>/<video>/` where both `../brand.lock.json` and an accidental local `brand.lock.json` exist → `../brand.lock.json` wins.
    - Standalone `videos/_template/` (no `../brand.lock.json`, local `videos/_template/brand.lock.json` exists) → falls back to `./brand.lock.json`.
  - Invariant: a video created in `videos/<brand>/<video>/` always inherits `videos/<brand>/brand.lock.json`.
- R2 (`F-13`): `videos/_template/scene.gen.cjs:6,25` loads `lock` before reading canvas dimensions and sets `const { width: W, height: H, duration: D, fps: FPS } = lock.canvas;` and `fps: FPS` in `scene` (`videos/_template/scene.gen.cjs:25`).
  - Partitions: `_template/brand.lock.json` (`1080×1920`, `duration: 4`, `fps: 30`); custom brand lock (`1920×1080`, `duration: 12`, `fps: 60`).
  - Invariant: generated `scene.json` top-level `size`, `duration`, and `fps` match `lock.canvas` `[width, height]`, `duration`, and `fps`.
- R3 (`F-02`): `lib/objects.cjs:20-44` (`metricCard`) strips card-specific keys (`bgColor`, `border`, `titleY`, `titleFont`, `titleSize`, `titleWeight`, `titleColor`, `counterY`, `counterH`, `counterSize`, `counterColor`, `glow`) from `extra` before passing the remaining `groupExtra` (e.g. `shot`, `name`, `anim`, `tracks`, `opacity`) to `group(...)` at `lib/objects.cjs:43`.
  - Partitions: `extra` with card styling keys + `shot: "s3"`; `extra` with only `shot: "s1"`; `extra` omitted.
  - Invariant: the returned `group` object never contains `bgColor`, `border`, `titleY`, `titleFont`, `titleSize`, `titleWeight`, `titleColor`, `counterY`, `counterH`, `counterSize`, `counterColor`, or `glow` as top-level properties on the group, while child `bg`, `titleEl`, and `counterEl` still receive their configured values and the group retains `groupExtra` (`shot`, `anim`, `tracks`).

### Trade-offs & Mitigations
- D1. Pros: eliminates silent `sample-brand` shadowing in every copied video while keeping `node videos/_template/scene.gen.cjs` runnable in place. Cons: a video inside a brand folder cannot override `brand.lock.json` locally without editing `scene.gen.cjs`. Mitigation: per `DESIGN.md` and `014/R2`, per-video palette overrides belong in `palette.json`, never in a duplicate `brand.lock.json`.
- D2. Pros: new videos automatically inherit canvas dimensions, duration, and FPS from the brand snapshot (`lock.canvas`) without manual edits. Cons: evolves Spec 011's initial convention where only `duration` was inherited. Mitigation: `scene.gen.cjs` can still override `W`, `H`, `D`, or `FPS` explicitly; `DESIGN.md` and `CHANGES.md` are updated to keep contracts in sync.
- D3. Pros: eliminates unknown-field notices when building `metricCard` scenes in Lienzo; forwards legitimate group properties (`shot`, `anim`, `tracks`, `opacity`). Cons: explicit destructuring key list in `metricCard`. Mitigation: backwards-compatible with existing callers and keeps `extra` as a single options object.
- D4. Pros: full support for all 4 Lienzo font roles (`heading`, `body`, `mono`, `accent`) in `brandFonts` and `label`. Cons: slightly wider object shape returned by `brandFonts`. Mitigation: `mono` and `accent` are only present when declared in the brand lock, preserving 100% byte-identity for brands declaring only `heading` and `body`.
- D5. Pros: environment backdrops (`sea`) and ambient particle fields (`particles`) can be bound to shots (`shot: "s1"`) and receive visual properties directly. Cons: additional optional parameter on `sea` and `particles`. Mitigation: default `extra = {}` preserves byte-for-byte output on existing calls.
- D6. Pros: closing shot titles can hold on screen without fading out prematurely (`DESIGN.md:50`), and `nativeShot` supports shot transitions. Cons: slightly wider signature for `nativeShot`. Mitigation: `transition` is optional; existing calls omitting it produce byte-identical shot descriptors.
- D7. Pros: lightweight pure helper extracting `inspect.notices` so skill scripts can surface font installation warnings. Cons: new export in `lib/brand.cjs`. Mitigation: single-line pure function; registered in `skills/lienzo-animate/SKILL.md` to satisfy `lib-list.test.cjs`.
